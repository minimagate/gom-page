# AGENTS.md, GOM Page Publication Guide

This repository publishes the public Geometry of Meaning archive. The sibling research
repository at `../geometry-of-meaning` is the source of truth for corpora, experiment protocols,
immutable runs, notebooks, metrics, and figure builders. This repository owns editorial pages,
site templates, chart-import manifests, and generated public chart copies.

## Repository Map

| Path | Purpose | Editing rule |
|---|---|---|
| `content/experiments/` | Method and design pages | Write from research protocols; keep results in observations |
| `content/observations/` | Run-backed analytical reports | Tie every quantitative claim to a named immutable run |
| `content/data/` | Public corpus documentation | Derive membership and metadata from canonical corpus files |
| `data/observation-charts/` | Chart import manifests | Edit manually; one manifest per observation slug |
| `scripts/sync_observation_charts.py` | Validated research-to-site chart importer | Extend carefully; it injects the grayscale style and automatic-height bridge |
| `static/charts/` | Imported self-contained Plotly HTML | Generated by the sync script; never edit manually |
| `templates/` | Zola presentation and shortcodes | Keep markup accessible and content-independent |
| `static/styles/` | Shared site styling | Preserve the narrow editorial layout and responsive behavior |

## Source-of-Truth Rules

- Never invent, duplicate, or silently correct research data in this repository.
- Never modify anything under `../geometry-of-meaning/runs/`; runs are immutable.
- Read the pinned run's `manifest.yaml`, `summary.json`, metric tables, experiment README, config,
  and objective notebook before reporting results.
- Name the run ID, model, population, aggregation, and projection basis near the claims or chart
  captions they support.
- Separate recorded measurements from interpretation. State limitations and avoid causal or
  language-intrinsic claims that the design cannot identify.
- Keep experiment pages methodological. Put run outcomes, synthesis, and limitations in the
  corresponding observation page.
- Every experiment explanation must name and link its input corpus to the matching `/data/` page.

## Chart Publication Contract

1. Build charts from immutable run artifacts in `../geometry-of-meaning` using the experiment's
   showcase builder and shared Plotly conventions.
2. Export generated HTML below
   `../geometry-of-meaning/artifacts/showcases/<area>/<experiment>/<run-id>/`.
3. Declare selected exports in `data/observation-charts/<observation-slug>.json` with unique public
   filenames.
4. Run `python3 scripts/sync_observation_charts.py --observation <slug>`.
5. Reference every selected output from the observation with the `plot` shortcode and a precise
   caption.

The sync script injects a grayscale visual-style block and a same-origin height-reporting bridge
into every imported chart. Website charts use luminance, line, marker, and pattern encodings rather
than hue; do not reintroduce colorful Plotly palettes in imported outputs. The parent listener in
`static/scripts/plot-frames.js` makes the iframe hug the chart's actual document height. Do not add
fixed heights, minimum heights, or aspect ratios to chart iframes. Do not bypass the sync script by
copying or editing HTML in `static/charts/`.

## Editorial Conventions

- Use stable lowercase kebab-case page slugs and chart filenames.
- Prefer this report sequence: question, design/provenance, results by analytical question,
  synthesis, inference limits, reproducibility, and source links.
- Choose a non-redundant chart suite. Each figure must answer a stated question.
- Captions must state the measure, row count or aggregation unit, relevant filters, run ID, and
  projection caveat where applicable.
- Link to the experiment protocol, objective notebook, immutable run, and summary when available.
- Preserve the existing visual language and typography. Avoid page-specific layout hacks.

## Validation

From this repository, run:

```sh
python3 scripts/sync_observation_charts.py
node --check static/scripts/plot-frames.js
zola check
zola build
git diff --check
```

Verify that every observation manifest output exists in `static/charts/`, appears exactly once in
its report, contains exactly one injected `gom-grayscale` style block and one `gom-plot-height`
bridge, and renders without clipping at desktop and mobile widths. Run focused research-repository
tests whenever a figure builder changes.

Preserve unrelated user changes in both repositories and report modifications separately for the
research and publication layers.
